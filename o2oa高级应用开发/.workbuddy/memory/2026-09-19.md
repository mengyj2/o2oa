## 2026-09-19（续）官方风格全套对齐 + 门户应用

### 需求
借鉴 O2OA 官方应用市场两个应用的截图风格与设计思路，完善五大应用：
- 合同管理：https://www.o2oa.net/market/app-77482a3d-1164-483b-9fa3-5cdbf91e8306.html
- 人力资源：https://www.o2oa.net/market/app-b11ead15-5243-4e93-bdf0-cb854671b9b2.html
决策：**改造深度 = 全面对齐（表单+门户+导航+视图）**；**字典对齐 = 两者结合**。

### 一、合同管理应用完全重建（14 表单 / 13 流程 / 9 视图 / 8 统计 / 8 表 / 9 查询 / 1 门户 4 页）
严格对齐官方四大分区：档案管理 / 过程管理 / 收款管理 / 付款管理
- 官方导航树、14 个工具栏按钮顺序、列表页 7 列、门户两张图 —— 全部照截图还原
- 合同状态口径 = 官方 4 终态（履行中/已终止/已解除/已中止）+ 流程中间态（草拟/审批中/已生效/已完成）= 8 项

### 二、官方表单版式落地（`o2oa_page.py` 扩展）
新增 API，全部用于五应用 36 个表单：
1. `open_section(sid, title, flatten=False)` —— 业务分区（Div + 左蓝竖线灰底标题）
2. `open_label_td` / `open_value_td` —— 官方「字段名格 + 值格」（标签格浅米色 `#faf8f4`、右对齐、110px）
3. `field_grid(gid, fields, cols, section_title=)` —— **核心**，自动生成官方表格式网格
4. `section_title=` 让分区标题以「跨列标题格」形式落在表格首行，比独立 Label 少一层 DOM

### 三、【重要修正】`_auto_page()` 升级
`FormBuilder._auto_page()` 从「Div 边框 + 单字段 td」旧版式，改为官方表格式：
`表头 → 分区(Div) → field_grid(标签格+值格) → 附件区 → 意见区 → 操作条`
→ 项目管理/预算/财务/档案四应用的 22 个表单**自动**获得官方版式，无需逐个改写。

### 四、新增门户应用（此前完全缺失）
**源码级确认 `WrapPortal` 结构**（`x_portal_core_entity/.../wrap/WrapPortal.java`）：
- `WrapPortal extends Portal`：`id/name/alias/description/availableIdentityList/availableUnitList/portalCategory/icon/firstPage/controllerList/creatorPerson/lastUpdateTime/lastUpdatePerson/pcClient/mobileClient` + `pageList/scriptList/fileList/widgetList`
- `WrapPage extends Page`：`id/name/alias/description/portal/data(String 10M)/mobileData(String)/hasMobile(Boolean)`
- **`Page.data` 是 HTML 字**符串**（不是 JSON），门户渲染器注入 iframe

新增 `build/o2oa_portal.py`：
- `portal_page_html()` 复刻官方门户：顶栏 + 品牌条 + 左侧树导航（带角标）+ 右「待办/已办」列表卡片 + 两张统计图
- 图表用**纯 CSS/SVG 手绘**（饼图含引线标注、柱图含网格线），不引第三方库，离线可用
- 官方配色：品牌蓝 `#2b6cb0`、饼图四色 `#4a8fe7/#f28b82/#4a5568/#f5c542`

新增 `o2oa_builder.py`：`portal()` / `portal_page()` 工厂函数
`pack.py`：`portal_list=portals`，并导出每页 `.html` 供直接预览

### 五、字典扩充（12 → 19）
- `dict_contract_status` 补第 8 项「已中止」
- 新增 7 条合同专有：`partnerType/receiveType/invoiceType/changeType/ticketType/planStatus/approveStatus`

### 六、【踩坑修正】两个校验器缺陷
1. **V6 误报**：`LEAF_TYPES` 漏了 `Datagrid`。Datagrid 放在 `<td>` 里是官方标准用法
   （合同审批表的付款计划明细），必须计入。新增 `CONTENT_TYPES = LEAF_TYPES | {Datagrid, Subform, Datatable, Tab}`
2. **V9 深度虚高**：父子推导时 **Div 层层嵌套**，导致第 N 个分区被算成第 N 层。
   官方表单里**每个分区都是 form 的直接子节点、彼此平级**。
   修复：遇到新 Div 时把所有已入栈的 Div（及其内部 Table/Td）全部弹掉。
3. V9 阈值从 6 层放宽到 14 层（官方版式固有 4~13 层，我加注释说明）

### 关键教训
**表单嵌套问题是静默失效的**——JSON 合法、导入不报错，只是渲染效果全错。
必须在打包阶段用程序化校验拦住，不能靠导入后肉眼发现。
