一、应用落地（第八 / 九轮）

1. 组件「编辑确定无反应」根因与正解

根因前端 chunk ComponentDeploy 的 OK handler 整体 async 无 try/catch； 其调用的 t.dispatchResource 在 10.0.2 线上 api.json 中根本不存在 → TypeError: undefined 未捕获 → 静默失败。挂 zip 必现，与登录身份/zip 内容无关。
正解组件资源 UI 是错入口。正确链路： POST /x_program_center/jaxrs/deploy/web/resource/as/new/{asNew}（Web 资源部署） + POST /x_component_assemble_control/jaxrs/component（注册表条目）。 手法：逆向接口有无看 war 内 describe/*.java + api.json；容器内 curl + docker cp 取回分析。

2. 19 个 zip 应用离线安装（方案A 落地）

鉴定19 个 zip 均为应用市场包（setup.json+xapp/*.xapp+data/web/custom）。 其中 2 对同 id（PDF预览/webserver资源管理、流程维护/自建表维护=空壳复制）。
接口POST /x_program_center/jaxrs/market/install/offline（multipart 字段 file），断云安全； 不建 Application 实体，写 InstallLog。
执行整目录 docker cp 进容器循环安装，19/19 status=1（同 id 幂等覆盖）。 InstallLog 中项目×6、合同/预算/财务/档案×2 仅为安装记录冗余，模块层各仅 1 实例 → 无功能重复。
冒烟Playwright+Edge（mengyijie）实测桌面标题正常、0 页面错误；办公中心待办 16 条真实流转 → 系统真正跑起来。
注意market/{flag}/uninstall 对离线装应用必 500，卸载别走它。

二、数据层打通与门户补齐（第十 / 十二 / 十三轮）

1. 数据层真正打通（秘书长硬指令：「要真正的能用，不是二级链接，到最底层的数据层要通」）

取证31 张自建表定义+物理表+种子数据早已就位；问题只在视图层—— 106 视图中 40 个 xdata=NULL（恰为 6 应用的视图）→ 嵌视图渲染空白。
修复1视图 data 必须是字符串：o2oa_builder.view() 改 json.dumps(...)； 6 应用 QRY 全部 200，空 xdata 40→0。
修复2★ 本版本无 TablePlan：dealPlan() switch 只认 cms，table 类型视图执行链无实现 → NPE。 改走表行接口直读+前端渲染（无引擎依赖）： POST /x_query_assemble_surface/jaxrs/table/list/table/{flag}/row/paging/{p}/size/{s}（body {}）。 新增 table_holder() + _LIVE_JS.loadTables()。
E2EHR「员工档案」9 行真实员工、合同台账千分位正确、startWork 真实创建流程实例；七道校验全绿。

2. 澄清「没有门户怎么用」— 四应用完全可用

结论01 项目/03 预算/04 财务/05 档案四个"无门户"应用功能完全可用，入口是原生 「流程应用工作台」，不是门户。42 条流程全部 xstartableTerminal=all，桌面有现成页签「流程应用-××应用」。
定位门户=仪表盘/门面；流程应用工作台=真正业务办理入口。没有门户 ≠ 不能用。

3. 按 OA 惯例补门户 — 1 个聚合门户 + 5 个分类栏目页

设计门户 o1001001-biz-portal-…「业务管理门户」/ 分类=业务管理； 下挂 5 栏目页：业务总览/项目管理/预算管理/财务管理/档案管理（导航即分类，横向 Tab）。按「综合管理/业务管理」分组展示。
★核心 bug页内 Tab 点击无效：原用 openApplication 因 multitask=true 另开新页签 → 看着没反应。 修复：新增 gotoPortal() 遍历 layout.desktop.apps 命中当前门户实例，调官方 Main.toPortal() 复用同窗。
验证e2e_biznav.js → 导航切换 5/5 成功、页面错误 0；门户实例数恒为 1。 门户校验 16 页×0（全部接活数据）。

三、具体故障修复（第十四 / 十五轮）

1. CRM 百度地图 AK 失效弹窗（8 文件全闭环）

根因CRM 硬编码 2016 年旧 AK Qac4WmBvHXiC87z3HjtRrbotCE3sC9Zg 已被删除； verify 接口实测 {"error":201,"error_msg":"APP被用户自己删除"} → 百度 SDK 内置表 ta[201]="APP被您禁用啦。" → alert()。 触发点是 Main.min.js（进入应用即拉百度脚本），非 BaiduMap.js。
修复优雅降级：把"是否加载百度脚本"分支恒假短路（只置空 URL 不够，仍会 loadDom("") 拿回 HTML 报 SyntaxError、 再 load BDMarkerTool 报 ReferenceError）。覆盖 8 个文件（含易漏 Main.min.min.js、结构不同的 AddressExplorer.js）。
验证node --check 8/8 全绿；幂等复跑 8/8 nochange； Playwright E2E DIALOGS 0 / PAGEERRORS 0 / BDMarkerTool 请求 0 / 百度外网请求 0；残留 AK 仅 3 处且全在注释内。
固化已写回 E:\OA系统上线方案\客户管理.zip（备份 客户管理.zip.bak-20260921-135814），重装不被覆盖。

2. 启用「每月一号修改办公资产状态」定时代理

根因系统级定时代理存于 X.CTE_AGENT（非流程内 PP_E_AGENT）； 该代理 xenable=0 即「(禁用)」来源；cron 0 */30 * 1 * ?（每月1号每30分钟）。
实现管理接口需 manager token（本环境不可得）；改用直接改库—— O2OA TriggerAgent 每分钟实时查库，UPDATE CTE_AGENT SET xenable=1 即生效，无需重启。
验证冷启动后 14:28:10 触发并执行，日志实证 [script] PRINT 每月一号把办公资产状态修改为"未盘点" / 获取办公资产数量======0。
两点事实① 脚本目前空跑：CMS 无「固定资产」分类 → 查不到文档。要生效需建该分类或改脚本对接资产表。 ② cron 频率偏高（1 号 48 次），建议改 0 0 1 * * ?（每月1号01:00一次）。
