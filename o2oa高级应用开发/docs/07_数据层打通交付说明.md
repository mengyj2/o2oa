## 二、问题是什么

整改前，门户栏目页是「空壳」形态：

- 页面上只有标题和占位表格（表头在、数据全空）；
- 或者只是一个链接，点进去还要再跳一层才可能看到数据；
- 甚至点进去什么都不出来。

这不符合"真正能用"的标准。要求是：**门户 → 视图/数据源 → 自建表 → 真实行数据，一路通到底。**

---

## 三、根因（两层，都已定位到源码）

### 第 1 层：视图设计数据（`data`）类型错误 → 整个数据中心应用导入失败

6 个应用的 40 个视图，`QRY_VIEW.xdata` 全部为 NULL。原因是构建侧把视图 `data`
写成了**嵌套对象**，而服务端 `ActionCover$Wi` 反序列化时要求它是**字符串**：

```
can not convert jsonElement to class:...ActionCover$Wi
Expected STRING but was BEGIN_OBJECT at path $.viewList[0].data
```

一旦报这个错，**整个"数据中心"应用导入返回 HTTP 500**（流程、门户不受影响，只有 QRY 模块挂）。

**修复**：`o2oa_builder.view()` 中把 `data` 改为 JSON 字符串：

```python
"data": json.dumps(view_data, ensure_ascii=False),
```

修复后 6 个应用 QRY 导入全部 200，`xdata` 为 NULL 的视图从 **40 个 → 0 个**。

### 第 2 层：★ 本版本视图执行层根本没有 `TablePlan` —— 自建表视图跑不起来

即使 `xdata` 填好了、`xtype='table'` 也写对了，视图执行仍然 **NPE**：

```
java.lang.NullPointerException
  at com.x.query.assemble.surface.*.ProcessPlatformPlan.adjustWhere(ProcessPlatformPlan.java:94)
```

源码实证（`x_query_assemble_surface` + `x_query_core_express.jar`）：

1. `BaseAction.dealPlan()` 是一个 switch，**只识别 `TYPE_CMS`**；
2. 其余类型（含 `table`）一律 `default` 塞给 `ProcessPlatformPlan`；
3. 而 `x_query_core_express.jar` 的 plan 包里**只有** `CmsPlan` / `ProcessPlatformPlan` / `StatPlan`，
   **没有 `TablePlan`**。

→ 本版本 `table` 类型视图在 surface 执行链上**没有任何实现**，必定抛 NPE。

旁证（库内取证）：

| 视图类型 | 数量 | 来源 |
|---|---|---|
| process | 56 | 系统自带 |
| cms | 36 | 系统自带 |
| **table** | **14** | **全部是本项目导入的** |

系统自带视图**从不使用 table 类型** —— 反证这个类型是半成品，官方 UI 里根本不产它。

## 四、方案：绕开视图引擎，直读自建表行接口

既然本版本的视图执行层走不通，就**不依赖它**。改用一条零引擎依赖的通路：

### 4.1 数据接口（实测可用）

```
POST /x_query_assemble_surface/jaxrs/table/list/table/{tableFlag}/row/paging/{page}/size/{size}
Content-Type: application/json
x-token: <token>
body: {}
```

返回：

```json
{ "type": "success",
  "data": { "count": 9,
            "data": [ { "employee_no": "YG001", "employee_name": "孟弋洁", … } ] } }
```

**关键细节**：返回的是**裸字段名**（`employee_no` / `employee_name`），
**不带 `x` 前缀**。物理列名带 `x` 前缀（`xemployee_no`），是**接口层主动剥掉了**。
写列定义时按裸名写，别加前缀。

同族接口还有：
- `POST .../table/list/{flag}/row/select`（body 传过滤条件）
- `GET  .../table/{flag}/row/{id}`（取单行）

### 4.2 生成侧实现（`build/o2oa_portal.py`）

**占位输出** `table_holder()`：

```python
def table_holder(table_flag, columns, caption="", height=None, page_size=50):
    """columns = [(key, 表头), (key, 表头, "money"|"num"|"date"), …]"""
    return '<div class="op-tbl-wrap" data-embed-table="%s|%s" data-page-size="%d">…</div>'
```

**运行时脚本**（必须放 `events.postLoad.code`，因为 Html 模块里的 `<script>` 不执行）：

```js
function loadTables(){
  document.querySelectorAll("#op-root [data-embed-table]").forEach(function(box){
    var parts = box.getAttribute("data-embed-table").split("|");
    var flag = parts[0], cols = JSON.parse(parts[1]);
    var size = parseInt(box.getAttribute("data-page-size") || "50", 10);
    req("/x_query_assemble_surface/jaxrs/table/list/table/" + flag +
        "/row/paging/1/size/" + size, "POST", "{}")
      .then(function(j){ renderTable(box, j.data.data, cols); });
  });
}
```

渲染细节：
- 表头 **sticky**，数字列**右对齐**；
- `fmtCell` 按第 3 个元素格式化：`money` → 千分位，`num` → 千分位，`date` → 截前 10 位；
- 空结果 → `.op-tbl-empty`；请求失败 → `.op-tbl-err`（**不静默**，否则又会变成"页面在但没数据"的假象）。

`boot()` 中两路互不影响：

```js
try { loadViews();  } catch(e){}
try { loadTables(); } catch(e){}
```

### 4.3 页面定义侧

`o2oa_hr_portal.hr_view_page_html()` 支持两种 section 形态，按长度自动判别：

```python
for sec in sections:
    if len(sec) == 4 and isinstance(sec[2], (list, tuple)):
        cap, tflag, cols, height = sec        # 表数据直读（table_holder）
    else:
        cap, app_id, view_id, height = sec    # 原生视图（view_holder，仅 process/cms 可用）
```

## 七、经验教训（可复用）

1. **导入 query 应用失败，先取完整 error message**，别只 grep 前 160 字符。
   `Expected STRING but was BEGIN_OBJECT at path $.viewList[0].data` 这种信息直接点名了出错字段。
2. **别在 ARM64/QEMU 下用 `docker exec`**：会持续 `setns` 失败（非瞬时）。
   但 `docker cp` 始终可用 → 取文件/看日志一律用 cp；跑不了命令时改宿主侧 Python urllib 调 127.0.0.1:9090。
3. **Python 读 Git-Bash 的 `/c/temp/...` 路径不通**，必须写 `C:/temp/...`。
4. **含中文路径的 PowerShell 脚本别经工具传参调用**：
   参数编码会被破坏成乱码 → `未能找到路径` 静默失败。
   Excel 模板校验因此改用纯 Python 版 `verify_excel.py`（zip + XML 直读，零依赖）。
5. **系统自带数据是反证的金矿**：系统自带视图从不用 `table` 类型，直接证明该类型不受支持。
   遇到"接口存在但不工作"，先看官方自己用不用。
