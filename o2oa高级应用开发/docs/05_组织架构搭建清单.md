# 组织架构搭建清单（导入应用前必做）

> 适用：中国复合材料工业协会 · O2OA 组织管理
> 关联交付物：`deliverables/*.xapp`（六个应用）
> 编制日期：2026-09-20

---

## 为什么要先做这一步

六个应用的**流程节点处理人不是写死的人名，而是脚本**。例如：

```javascript
// 「部门负责人审核」节点的处理人脚本
var dn = this.workContext.getWork().creatorIdentityDn;
var unit = this.org.getUnitByIdentity(dn);        // 先查发起人在哪个部门
var unitName = (unit && unit.name) ? unit.name : '';
return unitName ? this.org.getDuty('部门负责人', unitName) : [];
//                         ↑ 职务名        ↑ 部门名
```

脚本运行时去组织库里按**「职务名 + 部门名」**查身份（O2OA 的 `getDuty` 机制）。

**所以：脚本里出现的每一个部门名、职务名，都必须在 O2OA 里真实存在，且逐字一致。**
少一个字、多一个空格，都会查不到人。查不到时 O2OA 的默认行为是**把待办送给拟稿人本人**（官方口径），
表现为「流程莫名回到发起人手里」，很容易被误判成系统故障。

## 一、目标结构

```
中国复合材料工业协会                              ← 顶层组织（类型可填：社会团体 / 公司）
│   职务：秘书长 · 副秘书长
│
├── 综合部                    （1 人：人事 / 行政 / 财务 / 综合）
│       职务：部门负责人（秘书长兼）· 人事专员 · 财务专员 · 档案管理员 · 合同管理员
│
├── 研究技术部                （2 人：研究 / 行业 / 标准）
│       职务：部门负责人（秘书长兼）
│
├── 会员服务部                （会议 / 培训 / 展览）
│       职务：部门负责人（副秘书长兼）
│
└── 行业发展部                （行业推进）
        职务：部门负责人（副秘书长兼）
```

**分管关系**：秘书长分管 综合部 · 研究技术部；副秘书长分管 会员服务部 · 行业发展部。

**「部门负责人由分管领导兼任」在 O2OA 里的表达方式**：在该部门建一个名为「部门负责人」的
**组织职务**，成员选那位分管领导。这样脚本 `getDuty('部门负责人', 发起人部门)` 会自动得到
秘书长或副秘书长 —— **组织以后怎么调整，脚本都不用改**。

## 二、操作步骤

### 0. 进入组织管理

左上角主菜单 → **组织管理** → **组织架构**。

界面三块：左侧组织树（含「个人管理」入口）、中间/右侧组织信息、右侧信息区的
**「组织成员」「组织职务」** 两个标签页 —— 后面反复用到。

### 1. 建顶层组织

在「组织架构」页点左上角 **「+」**：

| 字段 | 填写 | 说明 |
|---|---|---|
| 名称 | `中国复合材料工业协会` | **必填，且必须与脚本一致** |
| 唯一标识 | `composites` | 建议英文，便于接口调用 |
| 组织类别 | `社会团体` | 可自定义；此处不影响脚本 |
| 排序值 | `1` | 整数 |

保存。

### 2. 建四个部门

在**顶层组织那一行右侧**点 **「+」**，逐个创建（这样上级组织会自动带上）：

| 名称 | 唯一标识 | 组织类别 | 排序值 |
|---|---|---|---|
| 综合部 | `zhb` | 部门 | 1 |
| 研究技术部 | `yjs` | 部门 | 2 |
| 会员服务部 | `hyfwb` | 部门 | 3 |
| 行业发展部 | `hyfzb` | 部门 | 4 |

> **唯一标识**在同一系统内不可重复，部门名在同一上级下不可重复。

### 3. 建人员

左侧 **「个人管理」** → 点 **「+」**：

| 字段 | 要求 |
|---|---|
| 人员名称 | **必填**（填真实姓名） |
| 手机号码 | **必填** |
| 唯一标识 | 建议填拼音，如 `zhangsan` |

把协会全体人员（含秘书长、副秘书长）都建上。重复「保存人员信息」逐条完成。

### 4. 加组织成员（建立「身份」）

O2OA 里人员与部门的关系叫**「身份」**。一人可在多个部门有身份（正是为兼职 / 借调设计的）。

对**每个部门**：选中部门 → 右侧 **「组织成员」** 标签 → **「添加」** → 勾选人员 → 确定。

> ### ⚠ 关键一步：分管领导也要加入所分管的部门
> 因为 O2OA 的**组织职务绑定的对象是「身份」**，不是「人员」
> （`UnitDuty.identityList` 的校验类型是 `Identity`）。
> 也就是说：**不在该部门里的人，无法被设为该部门的职务成员**。
>
> 所以请务必把：
> - **秘书长** 加入 **综合部**、**研究技术部**
> - **副秘书长** 加入 **会员服务部**、**行业发展部**
>
> 这不会让人数统计变乱 —— **身份数 ≠ 人数**，只是表达了「该领导在这个部门任职」。
> 综合部仍然只算 1 名员工。

### 5. 设组织职务（**最关键**）

对**每个组织**：选中 → 右侧 **「组织职务」** 标签 → **「添加」** →
在「职务名称」输入框填职务名 → 点该职务后面的 **「+」** → 勾选人员 → 确定。

要建的职务见下表（**职务名必须逐字一致**）。

| 所属组织 | 职务名称 | 成员 |
|---|---|---|
| 中国复合材料工业协会 | `秘书长` | 秘书长 |
| 中国复合材料工业协会 | `副秘书长` | 副秘书长 |
| 综合部 | `部门负责人` | 秘书长（兼） |
| 综合部 | `人事专员` | 综合部那位 |
| 综合部 | `财务专员` | 综合部那位 |
| 综合部 | `档案管理员` | 综合部那位 |
| 综合部 | `合同管理员` | 综合部那位 |
| 研究技术部 | `部门负责人` | 秘书长（兼） |
| 会员服务部 | `部门负责人` | 副秘书长（兼） |
| 行业发展部 | `部门负责人` | 副秘书长（兼） |

> **同一职务名可在不同组织重复**（源码：职务名的唯一性约束是「同一组织下不可重名」）。
> 所以四个部门都可以叫「部门负责人」，脚本按部门取值不会串。

### 6. 设汇报关系（可选，但建议）

用于「上级领导」类的处理人脚本（`this.org.listSupPerson(...)`）。

在**个人管理**里选中人员 → 编辑 → 找 **「主管」/「汇报对象」** 字段，指向其上级。

建议设置：

- 综合部、研究技术部的员工 → 主管 = **秘书长**
- 会员服务部、行业发展部的员工 → 主管 = **副秘书长**
- 副秘书长 → 主管 = **秘书长**

> 设了之后，「按汇报关系自动找上级」的流程节点即可工作，无需再依赖部门 / 职务名。
> 这是用户所说「或业务关系推导」那条路线的落地方式。

## 三、脚本会查的名字（对照检查表）

下表是**六个应用全部 42 条流程**实际会去查的「部门 + 职务」组合。
**任何一条在 O2OA 里查不到，对应的流程节点就会把待办退回给发起人。**

| # | 部门名 | 职务名 | 用在哪 |
|---|---|---|---|
| 1 | 中国复合材料工业协会 | 秘书长 | 各类流程的**终审**节点 |
| 2 | （发起人所在部门） | 部门负责人 | 各类流程的**分管领导审核**节点（自动跟随部门） |
| 3 | 综合部 | 人事专员 | 人事、考勤、员工自助类节点 |
| 4 | 综合部 | 财务专员 | 财务审核、出纳、预算、报销、收付款、开票类节点 |
| 5 | 综合部 | 档案管理员 | 归档、档案著录、借阅、移交销毁类节点 |
| 6 | 综合部 | 合同管理员 | 合同审查、登记、变更、签约方档案类节点 |

其中第 2 行是**动态**的：脚本先取发起人所在部门，再取该部门的「部门负责人」职务，
因此实际会命中 `综合部` / `研究技术部` / `会员服务部` / `行业发展部` 四个部门的同名职务。

## 四、验收自检（导入应用前逐条确认）

- [ ] 顶层组织名称是否为 `中国复合材料工业协会`（**逐字**，含「中国」二字）
- [ ] 四个部门是否为 `综合部` `研究技术部` `会员服务部` `行业发展部`（**不是**「综合办公室」）
- [ ] 秘书长、副秘书长的**顶层组织职务**是否已建，且成员已选
- [ ] 四个部门的「部门负责人」职务是否都已建、成员是否已选对应分管领导
- [ ] 秘书长是否已加入综合部、研究技术部；副秘书长是否已加入会员服务部、行业发展部
- [ ] 综合部是否已建 `人事专员` `财务专员` `档案管理员` `合同管理员` 四个职务

自查方法：建完后在**流程设计器**里随便打开一个流程，点开任一人工节点 → 人员标签 →
配置「职位」→ 搜索职务名，能搜到即说明搭建正确。

## 五、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 流程提交后又回到自己手里 | 节点处理人查不到，O2OA 默认送给拟稿人 | 对照上表检查部门名 / 职务名是否逐字一致 |
| 设部门职务时搜不到某位领导 | 该领导不是这个部门的成员 | 先在「组织成员」里把他加进这个部门（见步骤 4） |
| 同一部门想设多个「部门负责人」 | 一个职务可绑多个身份成员 | 点职务后面的「+」继续添加成员即可 |
| 部门改名后流程失效 | 脚本按名称查 | 改名后需同步改脚本；建议**只改职务成员、不改名称** |
| 综合部只有 1 人，却显示 2 个成员 | 分管领导以「兼职」身份加入 | 属正常，是 O2OA 表达兼任的标准方式 |

## 六、关于「秘书长的单子要签两次」

您的情形里有一个特例：发起人若属于**秘书长分管的部门**（综合部、研究技术部），
那么「部门负责人」和「终审人」都是秘书长 —— 线性流程会让他连签两次。

交付包已针对这一点做了处理：构建流程时会**自动插入一个选择节点**，
先比较「部门负责人」与「秘书长」是否为同一人：

- **不是同一人** → 正常送部门负责人审核，再进综合部、秘书长终审（三级）
- **是同一人** → 跳过部门负责人这一级，直接进综合部 → 秘书长终审（两级）

判断逻辑写在路由条件脚本里，用的是 O2OA 官方的选择节点条件机制
（「选择节点出来的路由上配置条件，`return true` 走这条」）。
**这一步不需要您在后台做任何配置**，导入即可生效。
