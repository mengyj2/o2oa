## 1.2 流程（7 条）

### ① 项目立项审批流程

```
[开始] → 项目申报 → 部门审核 → 专家评审 → 领导审批 → 项目档案归集 → [结束]
                        ↓退回修改    ↓不同意      ↓驳回
                     (回项目申报)  (回项目申报)  (回项目申报)
```

| 节点 | 类型 | 处理人脚本 | 绑定表单 |
|---|---|---|---|
| 项目申报 | 人工 | `return this.workContext.getWork().creatorIdentityDn;` | 项目基础信息表 |
| 部门审核 | 人工 | 取创建人的上级领导 | 项目基础信息表 |
| 专家评审 | 人工 | 取创建人的领导 | 项目基础信息表 |
| 领导审批 | 人工 | 取创建人的领导 | 项目基础信息表 |
| 项目档案归集 | 人工 | 综合办公室 / 档案管理员 | 项目基础信息表 |
| 结束 | 结束 | — | — |

**路由**：提交审核、同意、退回修改、同意立项、不同意、批准、驳回、归档完成

### ② 项目进度风险评审流程

```
[开始] → 进度填报 → 项目经理审核 → 主管部门审批 → [结束]
                          ↓退回
                       (回进度填报)
```

处理人脚本要点：项目经理环节用 `return this.data.manager;`（取表单里填的项目经理字段）。

### ③ 项目资金拨付审批流程

```
                                                                          出纳支付 → [结束]
                            ↓驳回（回报销申请）      ↓不通过（回报销申请）
```

```javascript
// 分管领导审批 → 主要领导审批（超额上报）
return this.data.expense_main.total_amount >= 5000;

return this.data.expense_main.total_amount < 5000;
```

# 八、元素 ID 命名规范

包内所有元素 ID 均遵循统一规则，便于识别与排障。

| 元素类型 | ID 格式 | 示例 |
|---|---|---|
| 应用 | `a{应用序号}{序号}-{英文名}-app-{补零}` | `a1001000-project-app-000000000000001` |
| 数据中心应用 | `a{应用序号}{序号}-{英文名}-dataapp-{补零}` | `a1001001-project-dataapp-0000000000001` |
| 表单 | `f{应用序号}{表单序号}-{英文名}-form-{补零}` | `f1001001-project-base-form-00000000001` |
| 流程 | `p{应用序号}{流程序号}-{英文名}-{补零}` | `p1001001-project-approve-0000000000001` |

**应用序号对照**：

| 序号 | 应用 |
|---|---|
| 1 | 项目管理 |
| 2 | 合同管理 |
| 3 | 预算管理 |
| 4 | 财务管理 |
| 5 | 档案管理 |
| 6 | 人力资源管理 |

以 `f1002003-xxx` 为例：`f` 表示表单，`1` 表示项目管理应用，`002` 表示该应用内第 2 类业务，`003` 是细分序号。**看 ID 前缀即可判断元素归属**，这在导入冲突排查时很有用。

> 各应用的 id 前缀段完整对照表见 9.1 节。注意 06 应用内部存在少量
> **编号与命名错位**（如表单 `f6006005` 名「员工离职表」，对应流程常量却叫
> `PROC_EMP_LEAVE_ID`），引用时以 `.xapp` 内实际 ID 为准，不要凭命名推断。

**重新打包**（一条命令产出全部成果）：

```bash
cd build
python pack.py                    # 生成 7 个 .xapp + 31 个 Excel 模板到 deliverables/
python validate_form_tree.py      # 表单结构，应为 0 错误 0 警告
python validate_dom_rebuild.py    # DOM 重建，应为 0 问题
python validate_xapp.py           # WrapModule 结构，应为 0 错误 0 警告
powershell -File verify_excel.ps1 # Excel 真机验证，应为 0 失败
```

> `pack.py` 的清理边界：只清 `_json` / `_xapp_json` / `*.xapp`，
> **保留 `deliverables/_excel`** —— 否则会把上次的 Excel 模板删掉。

**修改后务必执行校验**。`validate_xapp.py` 对照的是 O2OA 服务端 Java 实体类的
`_FIELDNAME` 常量清单，字段名拼写错误会立刻暴露，避免导入后才发现问题。
`validate_form_tree.py` 则专门拦截「模块层级写错导致导入后版式失效」这类
**不报错但界面全乱**的缺陷。
