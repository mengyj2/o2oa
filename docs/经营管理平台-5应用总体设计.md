> 路线：**声明式生成器全新构建**（不再克隆公文），统一现代 UI（左侧导航 + 卡片仪表盘，对齐用户参考截图）。

## 1. 统一 UI 框架（5 应用一致）

- **左侧导航 220px 白底**：应用 logo 区 + 分组菜单（组头 12px 灰、子项 34px 高 14px 字）；active 子项左 3px 蓝条 + 浅蓝底；分组点击折叠。
- **顶栏 60px**：页面标题（左）、用户名（右）。
- **主区 #f5f7fa 灰底**：卡片圆角 8px、微阴影。
- **仪表盘**：4 统计卡（彩色图标块 + 28px 大数字 + 13px 标签；数字由页面 load 脚本经 `this.Actions.load(...).ViewAction` 异步取数）+ 图表卡（原生 Stat 模块）+ 我的待办（View 模块）。
- **页面跳转**：导航子项 `this.page.toPage("页面名")`；页尾「应用切换」区放其余 4 个应用门户链接。
- 技术基线：页面运行时**只读 moduleList**；html 镜像提供容器层级（mwftype 占位）；表单控件复用已验证模板（Textfield/Textarea/Select/Calendar/Number/Personfield/Log）。

## 3. 数据与流程共享设计

1. **统一编号规则**（跨应用关联主键，表单 Textfield 填写、台账视图展示关联列）：
   - 项目 `PRJ2026xxx`、合同 `HT2026xxx`、预算条目 `YS2026-部门-序号`、报销 `BX…`/付款 `FK…`/收款 `SK…`、档案 `DA…`
   - 付款单填「合同编号」+「预算科目」；报销/付款填「项目编号」可选；档案条目填「项目编号」（项目结项归档）；预算编制填「项目编号」。
2. **跨应用数字聚合**：仪表盘统计卡脚本调 `this.Actions.load("x_query_assemble_surface").ViewAction.execute(viewId, {filterList:[]}, cb)` —— REST 无应用边界，项目管理仪表盘可直接取预算/合同/财务视图计数（运行时探测 `ExecuteV2/executeV2/Execute/execute` 方法名）。
3. **数据字典**：各应用 `applicationDictList` 存枚举（项目状态/合同类型/预算科目/档案类型/费用类别），表单 Select 以 `itemType:"script"` + `new this.Dict("字典名").get("键")` 读取（公文表单已验证此模式）。
4. **流程衔接**（一期人工衔接 + 单据提示，二期脚本自动联动）：立项批准 → 到预算管理编制该项目预算；项目结项 → 到档案管理登记项目档案；合同签订 → 付款在财务管理申请。

### 5.2 端到端实测（全链路打通）

发起 → 填报（写表单数据）→ 部门负责人审批 → PMO审核 → 分管领导批准 → 办结，全程 REST 驱动：

- **发起**：`POST /x_processplatform_assemble_surface/jaxrs/work/application/{app}/process/{proc}` body `{}`（**必须 switchuser 到真实用户**；xadmin 虚拟账号无组织身份）。
- **写数据**：`PUT .../jaxrs/data/work/{workId}`，**key 必须是表单字段唯一化后的 id**（如 `prj_code__f01`），不是字段名。
- **送审**：`POST .../jaxrs/task/{taskId}/processing`，body `{"routeName":"送下一环节名","opinion":"..."}` —— routeName 必须与路由名完全一致。
- **查待办**：`GET .../jaxrs/task/list/work/{workId}`（须用当前处理人 token）。
- **清理**：在途 `DELETE .../jaxrs/work/{id}/single/manage`；已办 `DELETE .../jaxrs/workcompleted/{id}/delete/manage`。
- **验证证据**：办结后 PP_C_WORKCOMPLETED 活动=结束、4 条 TaskCompleted 各环节意见完整落库；「项目台账」视图 execute 返回 1 行且全部业务字段有值（PRJ2026001 / 复合材料数字孪生平台 / 研发 / 120.5 万元）。
