# 智能助手集成度评估 —— 对照"四位一体"设计逻辑

日期：2026-09-19 ｜ 结论先行：**界面/数据层已基本达标；"上下文感知、权限边界、知识沉淀闭环、角色人设"四项是主要差距，其中权限越权是必须先修的安全硬伤。**

---

## 逐层对照

### 1️⃣ 界面集成：超级入口 —— ⚠️ 入口已有，"上下文感知"缺失

| 设计要求 | 现状 | 证据 |
|---|---|---|
| 嵌入工作台/悬浮窗/侧边栏 | ✅ 已有 | O2OA 前端 AI助手 入口经 18790 轮询 `/ai-gateway-mcp/list`（前端日志实锤） |
| 即时响应 | ✅ 已有 | chat/rag/mcp 三模式 + 流式；mcp 模式 4-18s/轮 |
| **上下文感知（识别当前场景）** | ❌ **协议层缺失** | **`x_ai_assemble_control.war` ActionChat.java 实测**：请求字段仅 `ClueId / Input / GenerateType / Person / ReferenceIdList / ThinkingEnabled / EndpointName / Content` —— **没有任何流程/表单/文档场景字段**，前端也不会把"你正在处理合同审批"传进来 |

**修法（关键洞察）**：协议加不了字段，但 **O2OA 前端是开源可改的** —— 在 AI 悬浮窗 JS 里把当前场景（流程名/应用名/文档标题）+ 当前用户 token 一起附加到请求（结构化前缀或扩展 JSON 字段，网关照单全收）。**一次前端改造同时解锁"上下文感知"和"身份边界"两件事。**

### 2️⃣ 功能赋能：从操作到决策 —— ⚠️ 半成品

| 设计要求 | 现状 | 差距 |
|---|---|---|
| 智能填报 | ❌ | 无表单上下文 + 无写回能力（依赖第1层场景 + 第3层行动能力） |
| 流程优化建议 | ⚠️ | 有 `query_data`/`report-query`（O2OA 快照问答）可查数，但无"流程瓶颈分析"专属工具 |
| 知识沉淀 | ✅ 基础已有 | RAG 索引（`/idx-gateway-*` 上传）+ skills 自主技能；**缺"对话中直接沉淀"**：`kb_save` 工具（把有价值的问答/结论一键入库供全员检索）不存在 |

### 3️⃣ 底层协同：数据互通与联动 —— ⚠️ 有数据、无边界、无闭环

| 设计要求 | 现状 | 差距 |
|---|---|---|
| 数据调用（授权范围内） | ⚠️ | `list_my_todo / search_org / query_data / report-query` 可用，**但全部走 xadmin manager token —— 越权硬伤** |
| **权限边界** | ❌ **安全硬伤** | ① `Person` 是前端自报字符串，网关无法验证；② 工具调用无身份隔离：**任何用户可借 AI 查到无权数据**（如他人待办、全组织数据）。`permissionList` 只护住了知识库，护不住工具 |
| 反馈闭环 | ❌ | 用户通过 AI 提的优化建议/错误反馈没有任何回流通道（无工具、无落库、无管理员视图） |

### 4️⃣ 角色定位：数字员工 —— ❌ 人设单一

- system prompt 固定一句话（"你是 O2OA 智能助手…"），**不区分**普通用户（向导）/管理员（参谋）/决策者（分析师）。
- 网关 `generate()` 甚至**没有读取 `person` 字段**（只读 ClueId/Input/generateType/permissionList/referenceIdList）——连"我在和谁说话"都不知道。
- 多轮记忆仅 clueId 关联的 10 条 kv，跨会话无记忆。

## 改进清单（按优先级）

| 优先级 | 项 | 内容 | 改动面 |
|---|---|---|---|
| **P0** | **权限边界（安全）** | 短期：`list_my_todo` 按 person 过滤为"本人待办"；`query_data`/`search_org` 保持只读 manager 但在 system 中声明能力边界；所有工具调用记录 person。长期：前端透传用户 token → 网关以**用户身份**调 O2OA REST | 网关小改 + 前端改造 |
| **P1** | **场景上下文** | 前端 AI 悬浮窗注入当前流程/应用/文档信息 → 网关解析进 system prompt（"用户正在处理《XX》流程审批"） | 前端 JS + 网关解析 |
| **P1** | **kb_save 知识沉淀工具** | 对话中一键把问答/结论入库（自动分块向量化），补齐"知识沉淀"闭环；顺带 `feedback` 工具落库 + `/gateway/feedbacks` 管理员查看接口 | 网关内置工具，小 |
| **P2** | **角色人设** | 按 person 是否管理员切换 system（向导/参谋/分析师三种话术与工具白名单） | 网关小改 |
| **P2** | **行动能力（写回）** | 代办创建/流程发起/文档保存——高风险，需白名单+二次确认，与 Agent Harness 一起后置评估 | 大 |
| **P3** | **体验细节** | ① mcp 模式工具执行期间先推"正在调用工具…"提示帧（现在缓冲导致等待感）；② 透传 `ThinkingEnabled`；③ 多轮记忆加深 | 网关小改 |

## 已达标项（无需动作）
界面入口、流式对话、知识库检索（含权限列表）、OCR 附件理解（扫描/表格/PDF）、多模态视觉、外部 MCP 生态接入、skills 自主技能、报表快照问答。

---

## 建议的落地顺序
1. **今天可做**：P0 短期版（person 过滤 + 日志）+ P1 `kb_save`/`feedback` 工具 —— 全在网关内，不动前端，一次交付。
2. **下一步**：P1 前端场景注入改造（需要动 O2OA 前端 JS，建议先在测试环境验证悬浮窗注入点）。
3. **其后**：P2 角色人设 → P2 行动能力（与 Agent Harness 合并设计）。
