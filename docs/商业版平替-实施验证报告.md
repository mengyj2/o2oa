## 三、★ 离线安装通道验证（任务 3，核心突破）

### 3.1 离线安装接口**完全可用**

**实测命令**：
```bash
POST /x_program_center/jaxrs/market/install/offline
  -H "x-token: <token>"
  -F "file=@package.zip;filename=xxx.zip"     # ★ 字段名必须是 file
```

**实测结果（成功！）**：
```json
{"type": "success", "data": {"value": true}}
```

**踩坑记录**：
- 字段名必须是 **`file`**（试过 files/upload/attachment/Filedata/data/zip 全部失败）
- 错误包会返回 `ExceptionErrorInstallPackage`（"错误的安装包"）—— 说明接口正常工作
- zip 内路径必须用**正斜杠** `xapp/verify.xapp`（反斜杠会导致解包异常）

### 3.2 离线安装包格式（源码确认）

```
xxx.zip
├── setup.json          # 应用元信息（必填）
├── custom/             # 可选：自定义应用（打包成 custom.zip）
├── xapp/               # 可选：.xapp 模块文件
├── web/                # 可选：前端资源
└── config/             # 可选：配置注入
```

**setup.json 结构**（来自 `Application2` 类 + 实测）：
```json
{
  "id": "唯一标识",
  "name": "应用名称",
  "category": "分类",
  "version": "1.0",
  "describe": "描述",
  "abort": "简介",
  "installSteps": "安装步骤",
  "vipApp": false,
  "restart": false
}
```

### 3.3 `.xapp` 格式（源码确认，`WrapModule` 类）

`.xapp` 是 **JSON 文件**，可含 5 类模块：

## 四、MinIO 方案验证（任务 4）

### 4.1 ★ 关键发现：O2OA **原生内置** MinIO 适配器

**证据**：`x_base_core_project.jar` 中存在
```
com/x/base/core/entity/MinFileSystemConfigBuilder.class
```

**支持的存储协议**（`StorageProtocol` 枚举）：
```
ftp · ftps · webdav · cifs · file · sftp · ali(阿里云OSS) · min(MinIO) · cos(腾讯云COS)
```

**MinIO 配置选项**（从 class 提取）：
```
serverSideEncryption  ·  disableChunkedEncoding  ·  useHttps  ·  taskTimeOut  ·  createBucket
```

**内置依赖**：`commons-vfs2-2.10.0.jar` + `commons-vfs2-jackrabbit2-2.10.0.jar`

> 注：标准 commons-vfs2 只带 ftp/sftp/http/local/zip 等，**min/ali/cos 是 O2OA 自行扩展的 provider**。

### 4.2 结论

| 问题 | 答案 |
|---|---|
| externalStorageSources.json 能顶替 MinIO 吗？ | **能，但要看用途** |
| 需要写插件吗？ | **不需要** —— `min` 协议原生支持 |
| 需要起 MinIO 容器吗？ | **需要** —— O2OA 只是"客户端"，要有 MinIO 服务端 |
| 不用 MinIO 行不行？ | **行** —— 可用 `webdav` / `sftp` / `file` 等其他协议 |

**`externalStorageSources.json` 支持 11 类业务存储**：
```
file · processPlatform · mind · meeting · calendar · cms · bbs · teamwork · structure · im · general · custom
```

### 4.3 建议

**分两步走**：
1. **暂不上 MinIO**：先用 O2OA **自带的文件存储**（默认 local）。单机自托管场景完全够用，附件存本地磁盘；
2. **需要时再上**：当出现「附件量大 / 要独立备份 / 要多节点共享存储」需求时，再在 compose 里加 MinIO 容器 + 配 `externalStorageSources.json` 的 `min` 协议。

**注意**：MinIO 是 VIP 应用指的是"**应用市场里的 MinIO 集成应用**"，但**协议层面 O2OA 是原生支持的**——所以自己起 MinIO 容器 + 手配 JSON 完全可行，不需要 VIP。
