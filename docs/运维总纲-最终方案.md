## 二、账号模型（根因 + 正解）

### 2.1 根因
- `xadmin` 是**虚拟初始管理员**，只存内存（`Config.token().isInitialManager()` 识别），**不在 `ORG_PERSON` 表**、无 identity。
- 用 xadmin 发起流程 → 后端报 `指定用户没有找到身份: xadmin.`
- 修复时陷入**硬校验死锁**：建人员时 `name`/`unique` 含 `xadmin`（含大小写不敏感、前缀匹配）均被拒「不能使用初始管理员标识」；建身份又要求 person 在 `ORG_PERSON` 真实存在 → 互为死锁。

### 2.2 正解（已验证）
**另建真实业务管理员**，不碰 xadmin：
- `unique=admin` / `name=系统管理员` / 密码 `o2oaadmin2026`，挂顶层组织（中国复合材料工业协会），授权 3 系统角色：`ManagerSystemRole` / `OrganizationManagerSystemRole` / `ProcessPlatformManagerSystemRole`。
- 幂等脚本：`tools/o2_fix_xadmin_org.py`（`check` / `apply` / `rollback`）。
- xadmin 留作纯后台账号。

### 2.3 组织 REST 契约速查
- list 多走 **POST**；`/person` 必填 `name`+`mobile`；`/identity` 必填 `person`(dN)+`unit`。
- 改密 = `PUT /x_organization_assemble_control/jaxrs/person/{name}/set/password`，字段名是 **`value`**（不是 password/newPassword）。
- 角色成员维护在 **role 侧**：`PUT /jaxrs/role/{id}` 提交完整对象、`personList` 写人员 id。
- `role/list/like` 空 key 返空 → 别用它查角色；改用已知 role id 直取。

## 三、应用模块「删除契约」（最核心沉淀）

> 一个"应用"横跨 5~7 层，只删一层会留孤儿数据或菜单死入口。**顺序强制，错序会被拦截或留孤儿。**

### 3.1 强制顺序
```
流程实例 → 流程应用 → 自建表定义 → 动态物理表(手工 DROP) → 数据应用 → 门户子页 → 门户 → 开始菜单项
```

### 3.2 各层接口与坑
| 层 | 动作 | 关键坑 |
|---|---|---|
| 流程实例 | `DELETE /x_processplatform_assemble_surface/jaxrs/work/{id}` | **在流转实例会拦删应用**，必须先清 |
| 流程应用 | `DELETE /x_processplatform_assemble_designer/jaxrs/application/{id}/false` | 即使 `false` 仍拦在流转实例 |
| 自建表定义 | `DELETE /x_query_assemble_designer/jaxrs/table/{tableFlag}` | `tableFlag`= `QRY_SCH_TABLE.xid` |
| 动态物理表 | `DROP TABLE IF EXISTS QRY_DYN_T{模块号}xxx_...` | **`deleteTable` 只删元数据不 DROP 物理表**（有意保数据）→ 必须手工 DROP |
| 数据应用 | `DELETE /x_query_assemble_designer/jaxrs/query/{dataappId}` | — |
| 门户子页 | `GET .../designer/jaxrs/page/list/portal/{id}` 后逐删 `DELETE .../page/{pageId}` | 先删全部子页再删门户 |
| 门户 | `DELETE .../designer/jaxrs/portal/{id}` | — |
| 菜单项 | 改 `applications.json` 两处 + `docker cp` + `restart` | 见 3.4 |

### 3.3 命名规律（按模块编号前缀定位全部关联）
- 流程应用 `a{模块号}*-app-*` ｜ 数据应用 `a{模块号}*-dataapp-*`
- 自建表 `t{模块号}*-table-*`，物理表 `QRY_DYN_T{模块号}*`
- 门户 `o{模块号}*-portal-*` ｜ 流程定义 `p{模块号}*`

### 3.4 开始菜单项两处同步（易漏）
流程应用在菜单里是 `applications.json` 的 `"@url:"` 条目，需改**两处**：
1. 补丁源 `patch/web/applications.json`（Dockerfile COPY，重建不复活）
2. 运行容器内 `/opt/o2server/servers/webServer/o2_core/o2/xDesktop/$Layout/applications.json`

```bash
docker cp "D:/O2OA/patch/web/applications.json" \
  'o2oa-server:/opt/o2server/servers/webServer/o2_core/o2/xDesktop/$Layout/applications.json'
docker restart o2oa-server   # 静态文件有内存缓存，必须重启
```
> bash 双引号内 `$Layout` 写成 `\$Layout` 防展开；也可用单引号包整路径避免转义。

### 3.5 误伤防护 + 基线核对
- 只按**精确 id / 精确名称**删除，绝不用宽泛 `LIKE` 做删除。
- `CPT_COMPONENT` 内置项（OnlyOffice/CRM/TeamWork/WpsOffice 等）**不要动**。
- 门户内展示页 ≠ 模块自身（删页不影响那些模块）。
- **删前/删后各跑一次基线**，确认目标残留全 0、其他模块计数只减预期值：

```sql
SELECT 'portal',COUNT(*) FROM X.PTL_PORTAL
UNION ALL SELECT 'pp_app',COUNT(*) FROM X.PP_E_APPLICATION
UNION ALL SELECT 'pp_process',COUNT(*) FROM X.PP_E_PROCESS
UNION ALL SELECT 'pp_work',COUNT(*) FROM X.PP_C_WORK
UNION ALL SELECT 'qry_table',COUNT(*) FROM X.QRY_SCH_TABLE
UNION ALL SELECT 'qry_query',COUNT(*) FROM X.QRY_QUERY
UNION ALL SELECT 'component',COUNT(*) FROM X.CPT_COMPONENT
UNION ALL SELECT 'cms_appinfo',COUNT(*) FROM X.CMS_APPINFO;
SELECT 'dyn_tables',COUNT(*) FROM information_schema.TABLES
 WHERE TABLE_SCHEMA='X' AND TABLE_NAME LIKE 'QRY_DYN%';
```
判定：`component` 与 `cms_appinfo` **零变化**（变了即误伤）；目标四类残留全 0。

### 3.6 空壳应用快速删除（新增模式）
当应用 **0 流程 / 0 表 / 0 实例 / 仅一个空数据应用** 时（如公共数据 `a0000000-common-dict-app`）：
- 无需清 work 实例（没有）；直接 `DELETE` 流程应用 + `DELETE` 空数据应用即可。
- 删除前后仍跑 3.5 基线，确认 `pp_app`/`qry_query` 各减 1、`component`/`cms` 不变。

## 四、开始菜单「三源」机制

`Layout.Top.loadMenu()` 只吃三个来源：
1. `o2_core/o2/xDesktop/$Layout/applications.json`（默认 `[]`）—— 流程应用深链入口。
2. `GET /x_component_assemble_control/jaxrs/component/list/all` → MySQL `CPT_COMPONENT`，再经**硬编码 24 个内置名**过滤（`ActionCreate` 强制 `type=custom`）。
3. `GET /x_portal_assemble_surface/jaxrs/portal/list` → **仅 `pcClient=true`** 的门户显示。

> 流程 / CMS / 查询的 `createXxxAppMenu` 在 `Layout.js` 被注释 → **永不单独显示**。

**三层补登（幂等脚本 `tools/o2_sync_startmenu.py`）**：
- A. WAR 组件 `POST /jaxrs/component`（存 MySQL 卷，restart 不丢）
- B. 流程应用写 `applications.json` 的 `"@url:"` 深链：`/x_desktop/index.html?app=process.Application&option=<urlenc {id,appId}>`
- C. 门户置 `pcClient=true`（**必须 designer 端点** `PUT /x_portal_assemble_designer/jaxrs/portal/{id}`，surface PUT 返 405）

**权限模型**：报错 = `allowList`/`denyList` 交集；**两者都空 = 不校验**。

## 五、健康排查方法论

排查"模块是否真在运行"时，REST 列表接口常因权限/缓存返 404/500，**以 MySQL 为权威**：

1. **按创建时间圈定范围**：`WHERE xcreateTime>='2026-09-20'` 拉出自建模块清单。
2. **健康四维判定**：
   - 流程定义数：`SELECT COUNT(*) FROM PP_E_PROCESS WHERE xapplication IN (...) GROUP BY xapplication`
   - 在流转实例：`SELECT xapplication,COUNT(*) FROM PP_C_WORK ... GROUP BY xapplication`（>0 说明活跃）
   - 动态表真实数据：`information_schema.TABLES` 行数 `TABLE_ROWS`
   - 门户页数 + 页内容长度：`PTL_PAGE` 计数 + `CHAR_LENGTH(xdata)`
   - war 组件探活：HTTP 探端点返回 200
3. **基线 delta 法**：删/改前后各取一次全量计数（见 3.5），用差值证明"只动了目标、没伤其他"。

## 六、AI 网关栈（一句话 + 端口 + 故障判定）

- **定位**：Bionic agent 能力 + O2OA 内网数据闭环，**不把公网数据搬进系统**；联网两道闸默认关（`web_enable=false` 一行恢复，代码零删除）。
- **端口**：chat `8088` / embed `8089` / rerank `8092` / OCR `8091`；统一入口 `18790`。内置工具 29（含 `web_*` 为 31）。
- **模型**：已切 `qwen3.8-27b`（17.74GB / ctx 65536）；4GB 核显先卸后载，`mcp_max_turns` 8→14。
- **故障判定**：AI 助手报 `connect timed out` = **网关没在跑**（栈活着时容器→`192.168.1.5:18790` 实测 200）。服务号不存在则回落 `o2oa_user`(xadmin)。
- 详细架构见 `docs/Bionic与O2OA-AI结合方案.md`。

## 七、高频坑与加固清单

| 坑 | 现象 | 对策 |
|---|---|---|
| 库名 | `Unknown database 'o2oa'` | 库名是 **`X`** |
| xadmin 登录报"用户不存在或密码错误" | 三员接管锁死 | 查 `config/ternaryManagement.json`：`enable=true` 且三员密码空 → 置 `enable=false` 后重启 |
| 容器 QEMU 长跑病态 | Jersey SSE 读空、exec setns 失败 | `docker restart` 即愈；规避 exec，用 docker cp/HTTP |
| 静态文件改了不生效 | 菜单仍显旧 | 必须 `docker cp` 进容器 + `docker restart` |
| 应用删不掉 | `存在 N 个在流转中工作实例` | 先删实例（3.2） |
| cookie 污染 | 服务号请求被当成上一用户(500) | O2OA REST 走专用 client + 每请求 `cookies.clear()` |
| bat 乱码/不执行 | 中文乱码、命令不跑 | CRLF + UTF-8 无 BOM + `chcp 65001` |
| 后台进程被回收 | `cmd &` 调用结束即回收 | `run_in_background=true` 或交看门狗 |
| `.sh` 不执行 | 行尾 CRLF | `.sh` 必须 LF；容器 UTC+8h |
| OCR | 接口 400 | `POST {ocr_base}/ocr` 吃 **base64 JSON**（`file_b64`+`filename`），非 multipart |
