O2OA AI 栈「看门狗弹窗 / 9090 卡死」根因与看门狗持续化硬化手册

来源 2026-09-22~09-23 多轮排障对话完整沉淀 · 适用 本地 Docker 自托管 O2OA 10.0.2 + 本地 AI 网关栈

0. 一句话结论

  • 9090 卡死 ≠ 服务挂了：实测 curl http://localhost:9090/ → 200 / 4~7ms，容器首页是官方标准跳转页。
  • powershell / python 不停弹窗：真凶是 gateway/watchdog_ai_stack.py 陷入「误判 DOWN → 杀健康服务 → 重启」死循环，每轮拉起一个新 python.exe 进程 = 一个窗口。
  • 误判根因：healthy() 用 urllib.request.urlopen 默认走系统代理；代理（52068 假 502）劫持了 127.0.0.1 探活 → 失败 → 误判 DOWN。
  • 持久化方案：把看门狗设为唯一锚点——启动清代理 env、无窗拉子进程、按 pid 杀旧进程、纯 TCP 探活不误杀；restart bat 与开机 VBS 全部经看门狗（即「看门狗持续化」）。

2. 根因分层

2.1 部署脚本隐患（已修，非主因）

deploy_home_entry_local.ps1 旧版用 Get-ChildItem -Recurse 全盘递归搜索 index.html，大容量盘上疯狂刷 IO（IO 风暴把 QEMU 容器拖到短暂无响应，被误认为卡死）。修复后改「盘根一层受控列举」+ 分流版 docker cp 进容器（compose 未挂 webServer 卷，只写本地对运行中的容器无效）。隐藏真相：此前门户首页"分流"从未真正生效。

2.2 看门狗「误判 DOWN」死循环（主因）

watchdog.log 铁证：gateway(18790)/ocr(8091) 每隔约 40s 被 taskkill /F 杀掉再拉起，循环 20+ 轮；而 gateway.log 同期 GET /gateway/health → 200 全程连续。服务没死，是看门狗在误杀健康服务。

2.3 误判根因：探活走代理

healthy(url, token) 用 urllib.request.urlopen(req)，而 urllib 默认读取系统代理环境变量。一旦开了代理（本机 52068 假 502），探活 127.0.0.1:18790 被转发到代理 → 失败 → 误判 DOWN。同源铁律：本地探测一律 curl --noproxy "*"。

2.4 弹窗帮凶：子进程可见窗口 + GBK 解码崩溃

看门狗 subprocess.run(["powershell"/"netstat"/"taskkill"]) 没加 CREATE_NO_WINDOW → 每个子进程新分配可见控制台窗口。且把 netstat 的 GBK 输出按 UTF-8 解码 → UnicodeDecodeError: byte 0xbb，该异常被当成「服务 DOWN」参与误判（见 watchdog_stdout.log）。

2.5 子进程弹窗：venv 启动器丢失无窗标志

看门狗用 DETACHED_PROCESS(0x8) 拉子进程（"无控制台"），但 venv 的 Scripts\python.exe 是启动器，会再 spawn 基础解释器；父进程没有控制台可继承 → 孙进程被 Windows 新分配可见控制台。修复：创建标志改 CREATE_NO_WINDOW（隐藏控制台可被孙进程继承，整树无窗）。

2.6 9090 浏览器"卡死"真相

服务端实测 200 / 6ms，首页是标准跳转页。浏览器卡死 = 系统代理把 localhost:9090 也劫持了。解决：把 localhost;127.0.0.1 加入代理「绕过」，或临时关代理刷新即秒开。

2.7 容器 unhealthy 是误报

o2oa-server 状态 unhealthy 但 curl 9090 → 200。健康检查用了 docker exec，ARM+QEMU 下 exec 的 setns 失败（OCI runtime exec failed ... setns process）→ 误报 unhealthy。服务实际正常。

4. 看门狗持续化设计（核心）

「看门狗持续化」= 看门狗是唯一持久化/自愈入口，而非散落脚本：

  1. 单一来源：所有 AI 栈子进程只由看门狗拉起；restart bat 与开机 VBS 只做「按 pid 杀干净 → 隐藏拉起看门狗」。
  2. 启动自检即持久化：每次启动清代理 env、用 CREATE_NO_WINDOW 无窗拉子进程、按 pid+端口兜底杀残留、纯 TCP 探活不误杀。
  3. 可打包为分支：ai-stack-hardening/ 即运行态代码快照（gateway/ + deploy/ + startup/ + install.ps1），git 提交到分支 ai-stack-hardening，可 bundle/archive 分发复现。

5. 可复用经验 / 技巧

  1. 本地探活必绕代理：curl --noproxy "*"；urllib 装 ProxyHandler({})；httpx 设 trust_env=False。
  2. venv 启动器无窗：子进程创建标志用 CREATE_NO_WINDOW，勿用 DETACHED_PROCESS（孙进程会丢标志弹窗）。
  3. 代理会假 502 劫持 localhost：本机服务探活一律绕代理；浏览器卡 localhost 先查代理 bypass。
  4. 别用 -Recurse 全盘递归搜索：大容量盘 IO 风暴，改受控列举。
  5. 控制台子进程加 CREATE_NO_WINDOW；GBK 输出用 errors="replace"，否则 0xbb 异常参与误判。
  6. 容器 unhealthy 但 9090=200 → 多半是 docker exec 健康探针在 QEMU/ARM 下 setns 失败误报，服务正常。
  7. PowerShell .ps1 中文要用 UTF-8 BOM，否则中文 Windows 按 GBK 误报语法错。
  8. 按 pid 文件精准杀比按命令行匹配可靠（VBS 隐藏启动的 32 位 python 常查不到 CommandLine）。
