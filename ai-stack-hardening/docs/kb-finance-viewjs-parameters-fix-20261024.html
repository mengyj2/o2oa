财务门户 view.js 无参打开崩溃修复（reading 'application' 真身）

doc-rev v1.0 · 2026-10-24 · 适用 本地 Docker 自托管 O2OA 10.0.2（feature/o2oa-ai-stack）· 关联 秘书长要求④后半；驱动仓提交 d6a3100

0. 一句话结论

财务页（付款申请，财务管理 portal 97e0d459）在 App 或无参直开时，门户脚本 view.js 的 setWorkCount() 读 this.page.parameters.parameters.application——parameters 未传入时 .parameters 为 undefined，抛 TypeError: Cannot read properties of undefined (reading 'application')，postLoad 链中断，页面只剩「未找到数据」残页。已按「源文件改 + DB 同步」修复并双探针验证（无参/带参均 ERRORS 0）。

1. 根因（探针实证）

#环节事实证据

2. 修复（源文件 + DB 同步，未走 designer API）

// [cnccia-patch 2026-10-24] App openAppNaviLeaf 未传 portalOptions 或无参直开页面时
// this.page.parameters.parameters 为 undefined，旧写法抛
// Cannot read properties of undefined (reading 'application')，postLoad 链中断、财务页只剩残页。
// 解构兜底；application 默认 finance（与 reimburseConfig 域标识一致）。
const pageParameters = (this.page.parameters && this.page.parameters.parameters) || {};
const parameter = {
    "application": pageParameters.application || "finance",
    "processList": pageParameters.processList
};

产物 patches/财务-viewjs-parameters兜底/：patch_fin_viewjs.py（xapp 外科补丁，锚点唯一断言+自动备份）+ update_viewjs.sql（DB 单字段同步）。

O2 xapp 的 JSON 转义是非标准约定：\" \\ \n \r \u0026(&) \u0027(') \u003c(<) \u003d(=) \u003e(>)，文本行尾 CRLF。踩坑：Python 里 '\\r\n' 少写一个反斜杠会让 \n 仍是换行符 → 锚点永不命中；正确写法 '\\r\\n'。
服务端脚本缓存：改完 PTL_SCRIPT.xtext 后页面 API 的 relatedScriptMap 仍返回旧文本，重启 o2oa-server 后才生效——改门户脚本后必须重启验证。
